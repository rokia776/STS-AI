# GlowDerma RAG Chatbot

A small Retrieval-Augmented Generation (RAG) project. It reads the **GlowDerma Skincare Knowledge Base** PDF, splits it into chunks, stores embeddings in a local Chroma database, and answers questions using only the retrieved passages. It can be used from the terminal or from a web page.

> GlowDerma Skincare is a **fictional company**. The PDF is a test document, and nothing here is medical advice.

## How it works

```
PDF  ->  split into chunks  ->  embeddings (bge-m3)  ->  Chroma DB
                                                            |
question  ->  embed question  ->  top-k similar chunks  ->  chat model  ->  answer + source pages
```

| Part | Model / tool | Provider |
|---|---|---|
| Embeddings | `baai/bge-m3` (1024 dimensions) | OpenRouter |
| Answers | `openai/gpt-4o-mini` | OpenRouter |
| Vector store | Chroma (saved in `chroma_db/`) | local |
| Chunking | `RecursiveCharacterTextSplitter`, size 900, overlap 200 | LangChain |

## Setup

1. **Create and activate a virtual environment** (PowerShell):

   ```powershell
   python -m venv .venv
   .venv\Scripts\Activate.ps1
   ```

2. **Install the packages:**

   ```powershell
   python -m pip install python-dotenv langchain-openai langchain-community langchain-text-splitters langchain-chroma chromadb pypdf flask
   ```

3. **Add your OpenRouter key** in a file named `.env` in the project root:

   ```
   OPENROUTER_API_KEY=sk-or-...
   ```

   No spaces around `=` and no quotes.

4. **Put the PDF in `data/`** with this exact name:

   ```
   data/GlowDerma_Skincare_Knowledge_Base_v1.0.pdf
   ```

## Usage

Run every command from the project root (`AI sts`), not from inside `src`, because the paths are relative.

**1. Test the embeddings connection** (optional)

```powershell
python src\ai_sts\task2.py
```

Expected output: `Vector dimensions: 1024`

**2. Build the database**

```powershell
python src\ai_sts\task3.py
```

This reads the PDF, splits it, calls OpenRouter for embeddings, and saves them in `chroma_db/`. It deletes and rebuilds the database on each run, which uses a little API credit.

**3. Inspect the chunks and the overlap** (optional, free)

```powershell
python src\ai_sts\task4.py
```

Writes `data/chunks_report.txt` (overlap marked with `<<<OVERLAP ... OVERLAP>>>`) and `data/chunks.json` (each chunk has `overlap_with_previous` and `overlap_text`).

**4. Ask questions in the terminal**

```powershell
python src\ai_sts\task5.py
```

Type a question, or `exit` to quit.

**5. Or use the web page**

```powershell
python src\ai_sts\app.py
```

Open <http://127.0.0.1:5000> in your browser. Each answer shows the pages it came from, and **Show the passages used** lists the exact chunks the model saw.

## Tuning

- **Chunk size and overlap** are set in `task3.py` and `task4.py`. Keep the values the same in both files. After changing them, run `task3.py` again so `chroma_db` matches.
- **Number of retrieved chunks** is `TOP_K` in `task5.py` and `app.py`. Increase it (for example to 6 or 8) for questions whose answer is spread across several sections.
- **Chat model** is `CHAT_MODEL` in `task5.py` and `app.py`. It must be a chat model, not an embeddings model.

## Troubleshooting

| Problem | Fix |
|---|---|
| `baai/bge-m3 is an embedding model and cannot be used with the chat/completions endpoint` | `CHAT_MODEL` must be a chat model such as `openai/gpt-4o-mini`. Keep `bge-m3` only in `OpenAIEmbeddings`. |
| `NameError: name 'embeddings' is not defined` | The `OpenAIEmbeddings(...)` block is missing at the top of the file. |
| `ModuleNotFoundError: No module named 'flask'` | Install with `python -m pip install flask` so it goes into the active venv. |
| `chroma_db not found` | Run `task3.py` first, from the project root. |
| `FileNotFoundError` for the PDF | Check the file is in `data/` with the exact name above. |
| Blank page in the VS Code Simple Browser | Open <http://127.0.0.1:5000> in Edge or Chrome instead. |
